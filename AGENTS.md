# AGENTS.md — PyPI Downloads Dashboard

## Project overview

PyPI Downloads Dashboard — a static web dashboard showing daily total downloads for any number of Python packages from PyPI. Data is fetched from the pepy.tech API via a Python script, stored in `pypi_downloads_data.json`, and rendered by a single `index.html` with Tailwind CSS via CDN. Zero build step.

## Architecture invariants

- **Single static HTML** (`index.html`) serves the entire dashboard — no bundler, no build step.
- **Data source**: `pepy.tech API` (requires `PEPY_API_KEY`), GitHub API (requires `GITHUB_USERNAME`).
- **Data persistence**: `pypi_downloads_data.json` and `github_stars_data.json` are generated by the workflow, not tracked in git. Deployed to GitHub Pages via `actions/deploy-pages`. APIs return full history, so each run regenerates the complete dataset.
- **Package list**: User-editable `pypi_packages.json` (JSON array of package names/slugs), `github_repos.json` (GitHub repos for stars).
- **Python scripts**: `src/my_stats_dashboard/update.py` (fetches downloads), `src/my_stats_dashboard/stars.py` (fetches GitHub stars) — both use `httpx` + `tenacity` for resilient API calls.
- **Local dev**: `make serve` runs `python -m http.server 8000`; `make update` runs both fetch scripts via `uv run`.

## Hard constraints

- **Never modify `pypi_downloads_data.json` or `github_stars_data.json` directly** — they are regenerated by the workflow. Preserve history via git commits.
- **`.env` is gitignored** — `PEPY_API_KEY` and `GITHUB_USERNAME` must never be committed; use environment variables or GitHub secrets.
- **All Python tool invocations MUST use `uv run`** — bare `python`, `pytest`, etc. will resolve to the wrong interpreter or missing dependencies.
- **Zero build step** — `index.html` must remain a standalone static file with no compilation/transpilation.
- **Tailwind CSS is loaded via CDN** — no local CSS build pipeline exists.
- **Date format**: ISO 8601 (`YYYY-MM-DD`) for daily keys in JSON data files.

## Known intentional behaviors — do not change

- `update.py` aggregates downloads across all versions per date (sums version-level counts).
- GitHub Actions workflow runs daily at 18:00 UTC (after pepy.tech updates at ~17:00) and on pushes to `pypi_packages.json` / `github_repos.json`.
- `stars.py` tracks a fixed owner (`barseghyanartur`) — changing this requires code modification.
- Test suite contains placeholder tests that require live API access; they are intentionally skipped in CI (no `PEPY_API_KEY` in public CI).
- `pypi_packages.json` and `github_repos.json` are flat JSON arrays — no nested structure.

## Data model

**`pypi_packages.json`** (input):
```json
["pytest", "requests", "flask"]
```

**`pypi_downloads_data.json`** (output):
```json
{
  "last_updated": "2024-01-15T18:00:00",
  "packages": {
    "pytest": {"2024-01-01": 1000, "2024-01-02": 1500},
    "requests": {"2024-01-01": 5000, "2024-01-02": 6000}
  }
}
```

Each package maps dates to total daily downloads (summed across all versions).

**`github_repos.json`** (input):
```json
["faker-file", "transliterate", "ska"]
```

**`github_stars_data.json`** (output):
```json
{
  "last_updated": "2024-01-15T18:00:00",
  "repos": {
    "faker-file": {"2024-01-01": 120, "2024-01-02": 125},
    "transliterate": {"2024-01-01": 80, "2024-01-02": 82}
  }
}
```

## Configuration authority

- **Runtime config**: `.env` file (local) / GitHub Actions secrets (CI) — `PEPY_API_KEY`. `GITHUB_USERNAME` auto-detected in CI via `github.actor`. `GITHUB_TOKEN` optional (increases GitHub API rate limit).
- **Package list**: `pypi_packages.json` (downloads), `github_repos.json` (stars).
- **Project metadata & deps**: `pyproject.toml` (uv-managed).
- **Dashboard UI**: `index.html` (static, self-contained).

**Step 4 — Fix failures, then repeat Step 3.**

**Step 5 — Run lint once more** to catch regressions introduced by fixes.

**Runtime rule — ALWAYS use `uv run`.** Never call `python`, `python3`, or any project tool directly — they will resolve to the wrong Python or missing dependencies. Every tool invocation must use `uv run`.
